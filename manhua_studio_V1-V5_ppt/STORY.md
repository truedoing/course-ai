# STORY.md · manhua-studio 电商出图管线 V1–V5 阶段任务地图

## ① 用户意图对齐
- **目标受众**：高职计算机专业学生（Python 课程改造班），课堂讲义 + 课后任务清单；同时给张老师备课对照。
- **核心目标**：让学生 clone 仓库后，清楚每一阶段（V1–V5）"要完成什么功能、交付什么、教师备什么"，并能对照验收三档自评。
- **PPT 长度**：12 页（封面 + 目录 + 总览 + V1–V5 五页 + 三种走法 + 验收三档 + 防躺平反思 + 结尾）。
- **视觉调性**：学术严谨 / 蓝白克制 / 证据驱动 / 结构化（命中学术风预设）。
- **内容边界**：必讲——V1–V5 各自功能、学生任务、新增构件、教师备课、验收三档；不讲——具体 API 参数细节、密钥明文、代码实现逐行。

## ② 页面布局骨架
- 章节：本 PPT 不分章，目录列为 5 个导航条目（总览 / V1–V5 / 走法 / 验收 / 反思），无 section 扉页（单线叙事，非多章结构）。
- Hero 页：P1 封面、P12 结尾（默认 hero）；中段无额外 hero，避免教学清单喧宾夺主。Hero 占比 2/12 ≈ 17%（满足 ≥2 下限）。
- rhythm：P1 peak → P2 transition → P3–P11 以 valley 承载信息（中间 P6 V3 为 peak：真家伙成型）→ P12 peak。
- 非对称版式预算：P3/P4/P6/P8/P11 用非对称双栏或左标题+右内容，P5/P7 用左标题+右内容，P9 用 N卡片横排（1 次，≤2），P10 用表格页。非对称占比 ≈ 8/12 = 67% ≥ 40%。
- 对称版式预算：仅 P9（三卡横排）、P10（表格），共 2 页。

### 各页要点（数据落点）
- P3：每版端到端可跑、是完整的（集成完整≠功能完整）；V1 只有白底图"不是没做完，是范围就到这里"——这是学生必须讲清的判断。
- P4–P8：每版给出"功能目标 / 学生任务(含交付物+命令) / 新增构件(代码位置) / 教师备课 / 验收三档"，让学生知道这版做到哪、差什么。
- P9：阶梯钩子让能力强的自然往上爬；一键包是入口不是差生标签——去污名化是设计意图。
- P10：期末硬线=所有人至少达期望档，挑战档加分；用反思单+口头2分钟低成本区分三档。
- P12：统一命令 `python -m manhua_studio --input 照片.jpg`；`git checkout vN` 回看任意阶段。
