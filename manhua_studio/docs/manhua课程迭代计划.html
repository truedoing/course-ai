manhua-studio 课程迭代计划

电商出图管线 · 5 版渐进（V1–V5）· 教师备课用 · 2026-09-25

一、目标与两条轴

最终目标：所有学生交付一份"像真家伙"的数据驱动商品页——真实 Seedream 出图、WebP 压缩、学号定位、配反思单。同一份交付物，不分快慢班。

轴 1 · 版本迭代（课程时间轴）：V1→V5 跨数次课逐步叠加构件，每版端到端可跑、是完整的，只是范围由小到大。非瀑布（不是最后才拼起来）。

轴 2 · 三种走法（学生能力轴）：同一版本内，弱/中/强学生拿不同厚度的支撑——跟跑（AI 基本写完，跑+读）/ 并跑（半成品，改 prompts）/ 领跑（裸引擎，自己写+排错）；三档都写代码，只是 AI 扶到哪一步不同。

"完整"的精确定义：集成完整＝这一版端到端跑通、非桩代码、能交真东西；不是功能完整＝不必含最终全部特性。学生需讲明：V1 只有白底图"不是没做完，是这一版的范围就到这里"。

二、版本总览（5 版渐进 · 难度逐版压低）

V1 去底白图
S1 + cli V2 场景图
S2 + prompts V3 商品页
sku + 页面 V4 识别闭环
S0 自动识别 V5 工程化
质检 + 排错

每版在前一版基础上叠加构件，老代码原样保留；建议占 5–6 次课（V3 页面是新概念，留 1–2 次）。

版本建议课次新增构件（manhua-studio 模块）学生当版交付物
V1 去底白图1 次S1 去底（adapters.py · stage1_remove_bg）＋ cli 入口1 张干净白底商品图（真实电商素材）
V2 场景图1 次S2 出图（adapters.py · stage2_scene）＋ prompts 模板（prompts.py）＋ mock/真实切换白底图 ＋ 2–3 张场景图（已压低：原 4 张→2–3）
V3 商品页1–2 次数据化（pipeline.py · write_sku_data）＋ 商品页 ＋ WebP 压缩（pipeline.py · stage_optimize_web）＋ 学号定位可浏览商品页——"真家伙"在此成型
V4 识别闭环1 次S0 智能识别（adapters.py · stage0_recognize）全自动照片丢入→全自动出全套（闭环）
V5 工程化收口1 次＋答辩质检筛选（pipeline.py · pick_best/count_status）＋ 错误处理（404/JSON 解析）＋ 归档日志生产级管线 ＋ 反思单 ＋ 口头 2 分钟

三、每版验收三档（最低 / 期望 / 挑战）

三档对应你已有的"验收三档"，不重画。弱生达标线＝最低档（靠写好的代码包），强生冲挑战档（改代码/排错）。一键包＝教师用 Yoo Code 写好的完整代码包（非黑盒），三档都写/读代码，只是 AI 扶持度不同。

版本最低（达标·一键包可达）期望（半成品可达）挑战（裸引擎可达）
V1用一键包跑出白底图并截图归档自己配 UAPI_KEY、跑命令出图读懂 cli 参数、改输出文件名
V2一键包出 2 张场景图自己写/调场景 prompts 模板在 generate.py 加一个自定义场景
V3一键包出商品页自己把商品名/卖点填进数据改页面样式或加一个数据字段
V4一键包跑通全自动看 S0 输出、判断识别质量微调识别 prompt 提升准确性
V5跑通并交反思单能描述一次自己遇到的报错修一个故意留的故障 / 加一个构件

四、三种走法支撑物（教师备课清单）

复杂度全挡在备课阶段，学生端只拿到清晰说明。下列物几乎都复用现有成果，不必新造：

走法给谁支撑物（教师准备）现有基础
一键包弱代码已写好：跟跑生 cp env.example .env 填 key 后，python -m manhua_studio --input 照片.jpg → 出 deliverables/学号/出图模式已是全自动；弱生拿到写好的代码包后直接 python -m manhua_studio --input 照片.jpg
半成品中填 config.json ＋ 调 prompts.py 模板的图文指引路径/参数已在代码中预设，或经 .env 配置；半成品走法主要改 prompts.py 模板
裸引擎强指到 adapters.py / pipeline.py ＋ 一张"故障练习卡"（故意留 404/JSON 错）模块化结构天然支持

另备反思单（三句话）：① 我做了什么 ② 我卡在哪/怎么过的 ③ 下次想改哪。弱生写"我主要跑了现成的，但看懂了 AI 能把一张照片变成一整套商品图"即合格；强生必须写出"我改了 adapters.py / pipeline.py 第 X 段 / 修了什么错"才给高分。

五、防"大家都躺一键包"

  • 阶梯钩子：L1（弱走法）产出可见地不完整——例如 V1 只出白底图，V3 才有完整页面，能力强的自然想往上爬。
  • 期末硬线：所有人至少达到"期望档"（中走法），挑战档加分；与验收三档挂钩。
  • 低成本区分：反思单 ＋ 口头 2 分钟，不靠监考。靠文字区分三档，比建三套体系轻得多。
  • 去污名化：所有人从 V1 跟跑起步；一键包是"入口"不是"差生标签"。

六、与三级火箭 / 工程使能的关系

  • 层级定位：本计划落在"一级语言底座"课内（Python/JS 班的电商出图项目模块），是学期宏观"三级火箭"里最底层的实做单元；版本迭代是这一单元的微观展开。
  • 为什么能"每版只激活下一构件"：昨日把 manhua.py 重构为 manhua-studio/（入口薄 / 引擎厚 / 适配器 adapters 与管线 pipeline 两层），V_n 只是多启用一个构件（adapters.py / pipeline.py 里的函数），旧代码原样保留、不会把上一版搞坏。若仍挤在单文件，每次加版都要手工删改，迭代就走不动。重构的教学价值在此。
  • 理论背书：逐步释放责任（Gradual Release of Responsibility）＋ 敏捷"可工作软件优先"，可写进你期刊投稿的方法论段。
