manhua.py PBL 教学场景与需求说明书

一级底座的"真实感"来源。学生只有先看懂"这是在干嘛、为谁干、图算不算合格"，构件（component）才不是老师的玩具。本文是 manhua.py 的教学 wrapper：场景设定 / 角色 / 需求 brief / 验收标准 / 分章任务 / 反馈环。

为什么必须有这份场景说明书

PBL（项目式学习）成立的前提是学生能指认"我写的代码对应真实世界的哪一步"。manhua.py 十一构件讲清楚了"怎么写"，但没讲"为什么世界长这样"。如果只发代码，学生会把 stage0_recognize、parse_products_csv 当成无意义的练习函数。本文补上"业务上下文"，让每个构件都有一句"在真实电商素材生产里，这一步是……"。

真实感分级见第八节：一级课内只到 L1 脱敏真实口径，不碰真店、不占算力。真店是三级可选，不是一级前提。

一、场景设定（学生看到的"世界"）

背景故事（脱敏改写自真实类目，非真实客户）。 「青瓷小铺」是一家做陶瓷文创的小店，主理人阿琳（店主）要在双11前把一批新品上架到淘宝、拼多多、抖音、小红书四个平台。阿琳懂设计和文案，但不懂 AI、不会写程序，也不清楚每个平台对主图的要求。她找到你们（学生团队）说："帮我出一套能直接上架的素材。"

你们做的事：把阿琳的口述需求，翻译成机器能跑的参数，批量生成素材，按平台规范质检、筛掉废片，最后交付"每个 SKU 一套合格素材 + 一份生产记录"。这正是 manhua.py 整条管线的业务原型。

阿琳口述需求→ 需求解析翻译成结构化→ 展开生成任务→ 出图(构件8)→ 质检筛废片(构件9)→ 交付合格素材包

伏笔：清单里有一个 SKU「阿瓷」是漫剧角色（Character(Product) 子类）。学生期末会发现"原来漫剧角色就是电商商品换了个子类"——同一套管线换一个类就能做漫剧，这正是选 A 决策的工程依据。

二、角色与分工（谁是谁，谁不干什么）

角色真实身份在场景里的职责与体系的关系
阿琳（店主）外部客户（脱敏）提需求、定卖点、最终验收"图算不算合格"一级的"客户"原型；二级/三级可换成真实商家
你（张老师）技术底座 + 全局设计搭管线、教连接器/批处理/OOP、定文件契约一级主讲 + 全局；精力侧重 FDE 方向
董老师（UI 老师）视觉资产架构者定"图算合格"的视觉标准与质检清单（B2/B4）主副配合：她侧重 AIGC 应用层验收，你不替她定标准
学生（交付方）Python 班 7-8 人核心写构件、跑管线、按清单自检课内全体打底，高质量核心自组织进二级
平台规则淘宝/拼多多/抖音/小红书白底、尺寸、文字占比、禁用语等硬约束验收标准的来源，是"标准化翻译成检查项"的教材

关键边界：一级里学生不碰经营、不碰真店、不碰客服。他们只做"需求→参数→图→质检→交付"这一段，经营是客户/董老师的事。这既保护精力，也守住"非校方、社团自愿"的红线。

三、业务流：一个商品上架到底要哪些图

学生常以为"出张图就行"。真实上架是多平台 × 多图型：

图型作用平台共性要求
白底主图搜索结果首图，决定点不点纯白底（RGB 255,255,255）、主体占图 70%–80%、无边框无水印
场景图使用情境，促进想象可带背景，但文字占比 ≤20%、禁用"最/第一"等绝对化用语
细节图材质/工艺特写，建信任清晰度高、对焦准确，漫剧角色需人脸完整
视频主图抖音/拼多多强要求通常 15–30 秒、不得含二维码/外链（属二级 B2 进阶）

这就是为什么一个 SKU 会展开成多条生成任务：4 个 SKU × 3 图型 × 跨平台 ≈ 29 条（manhua.py 实测即 29 条）。学生从"一张图"到"29 条任务"的认知跃迁，就是批处理（B1）要解决的真实问题。

四、需求 brief（人话 → 结构化）

阿琳给的是口述/半结构化文字，学生要翻译成 manhua.py 能跑的参数。下面是「 brief 原文」与「 stage0_recognize / parse_products_csv 解析出的字段」对照——这一步本身就是就业框架里最值钱的"需求翻译"能力。

① 原始 brief（学生读到的样子）

【双11 上新 brief】
1. 青瓷茶杯 | 类目:陶瓷 | 材质:釉面哑光 | 卖点:好看/耐用/手作 | 平台:淘宝,拼多多 | 主图:白底主图,场景图
2. 茶壶套装 | 类目:陶瓷 | 材质:粗陶 | 卖点:送礼体面 | 平台:抖音,小红书 | 主图:白底主图,细节图,场景图
3. 釉下彩盘 | 类目:陶瓷 | 材质:釉下彩 | 卖点:吃饭也有仪式感 | 平台:淘宝 | 主图:白底主图
4. 阿瓷(原创IP) | 类目:漫剧角色 | 材质:虚拟形象 | 卖点:人设吸粉 | 平台:抖音,小红书 | 主图:场景图,细节图

② 解析出的结构化字段（构件 0 需求解析产出，对应代码 stage0_recognize + parse_products_csv）

字段含义缺省处理
sku_codeSKU 编码（自动生成 TC-001…）顺序编号
name / category名称 / 类目（漫剧角色走 Character 子类）必填，缺则跳过并记入日志
material / selling_point材质 / 卖点（进提示词）空串
platforms目标平台列表默认 ["淘宝"]
shot_types图型列表（白底/场景/细节）默认 ["白底主图"]

真实感来源：字段全部贴 2025-2026 各平台商家后台公开规范（白底、文字占比、禁用语、视频主图时长）。brief 是脱敏改写，不冒充真实客户，但每个字段都经得起运营较真。

五、验收标准（图算不算合格）

这是"标准化翻译成检查项"的教科书实例，也是二级 B2（一致性）/ B4（质检）的雏形。验收权归董老师（视觉标准），不归你（技术底座）——主副配合在一级就咬合。

检查项判定（可机器化部分）谁定标准
白底纯度背景 RGB 接近 255,255,255 的比例 ≥95%平台规则（客观）
构图占比主体占图 70%–80%平台规则（客观）
清晰度高频细节可辨、无模糊董老师（视觉）
文字占比图内文字面积 ≤20%、无禁用语平台规则 + 董老师
人脸完整（漫剧）阿瓷类必须人脸完整、无畸变董老师（重写 score）

manhua.py 里 Product.score() 用白底纯度/构图比/清晰度/文字占比四项算出可判定分（真实模式 metrics 由二级 B4 复核）；Character.score() 重写了人脸项，所以阿瓷 0 合格/2 废片——学生能从"为什么同一管线两种结果"反推 OOP 继承/重写不是装饰。

七、反馈环：学生怎么知道"干得对不对"

一级课内（L1，现在就做）

反馈来自规则自检：跑完管线，生产记录里每张图有 status（done/failed/pending）和 score。学生对照验收清单自己判"废片率为啥高"。无需真实客户、零算力、规则自检即可。

真实感到此足够：场景像真的、规则是真的、质检逻辑是真的。

二级/三级（L2/L3，后续）

反馈来自真实客户：阿琳（或真实商家/董老师的店）说"这张卖了/那张没过审"。这时 manhua.py 的 status 字段天然对接文件契约，学生出的图直接进入真实交付流。

L2/L3 才需要真图、真算力、真客户，与一级解耦。

八、真实感分级（明确一级到哪、真店在哪）

等级含义算力客户落在哪一级
L0纯假习题（传统课本）0无改造前
L1脱敏真实口径 brief + 真规则自检0（规则自检，无需算力）虚构阿琳一级课内（本文目标）
L2真实商家当客户给 brief+反馈二级 1.5-2千真实商家/校友二级训练营
L3真开店（微店/抖店）自运营三级另计自有店三级核心组（可选）

关于"自己真开店"——结论

一级 PBL 真实感到 L1 就够，不需要自己开店。开店带三类成本，与体系命门（精力分配）冲突：

① 钱：保证金/押金/类目资质；店不卖即 PPT 项目，踩逆向判据（无真实结果的"真实项目"=假真实）。
② 精力：客服/物流/退换货，和"精力倾斜 FDE"直接冲突。
③ 主体红线：已定非校方、社团自愿；学生开店涉经营资质与收益归属，个人开占家人精力。

更划算的三条路（按性价比）：
1. 找真实商家当客户，不自己开店（最推荐）——本地小老板/校友/家人朋友小店给真实 brief+反馈，学生当交付方。80% 真实感、20% 成本，且与 FDE"真实客户"同逻辑；还能把"电商素材客户"与"FDE 校内客户"分开找、互不依赖，缓解客户源待定项。
2. 董老师开自己店当测试床（OPC 视角）——她定位视觉资产架构者，微店/抖店是她的副业试验田；学生出图、她验收+上架。店是她的，学生不碰经营，家属线与真实交付合流。
3. 真开店放三级/下学期——仅当二级跑通、核心组自组织成型、有真成交预期才做；一级永远不碰真店。

一句话：一级现在建 L1 场景；真店从"必需"降级为"三级可选"，优先走"真实商家当客户"或"董老师开自己店当验收方"。

九、与二级/三级的接口（一级不止是"写作业"）

一级产出的 results/meta.json（每个任务 status 三态 + score）天然是未来与 JS 工具组、与真实客户之间的文件契约雏形。一级学生毕业时交的不是"一个 py 文件"，而是"一套合格素材包 + 生产记录 + 一份能对接真客户的字段说明"——这正是二级 B1-B5、F1-F6 要放大的那八成主干的起点。

课内教"分叉之前的那段"（连接器 + 单件脚本），二级把八成主干放大成工程能力。课内不必在电商/漫剧间二选一——它们共享同一个 Product 基类。
