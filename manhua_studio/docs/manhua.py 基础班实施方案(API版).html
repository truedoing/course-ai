manhua.py 基础班实施方案（API 版）

三级火箭 · 一级语言底座（课内必修）· 真实电商 AI 出图闭环 · 修订于 2026-09-22（V5 真实闭环 · Seedream 4.0）

一句话定位：manhua.py 是贯穿 Python 课的教学主线脚本，学生从"拍一张真实产品照片"出发， 用 API 完成"去底白底化 → 场景化/多版本生成 → 质检交付"的真实电商出图闭环， 每个章节往脚本里加一个构件（component），期末拼成一条完整管线。

本方案只服务基础班（一级课内）：全 API 本地模型下放二级社团，学生任意机器零本地依赖即可运行。

实测更新：经端到端测试，Seedream 4.0（火山方舟 doubao-seedream-4-0-250828）的 image 参考图生图能够可靠保留原产品外观， 并把白底产品自然放入"手拿/办公桌/户外/车载/礼盒"等场景。因此 S2 场景化已切换为 Seedream 4.0 参考图生图， S1 去底仍用国内免费抠图 API「UAPI / uapis.cn matting」。全 API / 零本地模型原则不变。

1. 为什么是这个方案（修订依据）

原方案被推翻的点

  • 原"文本描述产品 → 生成产品图 → 上架卖"经核对是编的：真实商家不会凭空编一个产品画图去卖（虚假宣传红线）。
  • 原"新品概念图 / 调研"场景经核对不成立：中小电商商家基本不做"用 AI 图做市场调研"；大企业有生产前概念渲染，但非电商运营主流。

真实闭环（有公司名+数据实证）

  • 天猫"家作"：商家上传商品图 → 一键生成 80+ 风格场景图；慕思一年采纳近 2000 张、省 140 万；上线一年 13 万+ 商家（新浪财经、AIBase）。
  • Photoroom / remove.bg / 稿定抠图：随手拍 → AI 去背景加白底，一次拖 200 张几分钟搞定（flowpix 实证）。这正是"白底不好拍"痛点的真实解法。
  • 图小玉 / 千多 AI：上传白底原图 → 零基础运营批量生成场景套图（今日头条案例）。
  • 服饰铺货团队 A/B 测试：已有真实连衣裙，换场景图测点击率；作者如实标注"转化率未同步提升、样本仅 20 款、不确定是否纯归因"（真实不粉饰记录）。

2. 分级策略（三级火箭的自然映射）

层级去底/生成技术理由
一级 · 基础班（课内） 全 API 云端去底 + 云端生成 学生本地环境各异，不碰本地模型；任意机器联网即跑，维护成本归零，契合"薅免费额度"成本策略。
二级 · 社团训练营 本地模型 RMBG-1.4 等 进阶改造 自驱学生在二级深化：本地推理、批量工程优化、微调、离线管线——作为一级的"工程深化版"，不进入课内考核。
该分级让一级"稳"、二级"深"，与既定"主副配合 + 自组织"的精力分配完全一致：课内只保 API 闭环，重活留给社团自驱者。

3. 基础班四阶段管线

0
输入 · 学生拍照（--input 照片.jpg）
手机任意背景拍一张真实产品照（如一只杯子）。无需影棚、无需白底——这一步本来就是"白底不好拍"难题的入口。
1
S1 去底白底化（UAPI 免费抠图 · uapis.cn matting）
任意图（学生随手拍）→ 纯白底图（RGB 255,255,255）。学生本地照片直接上传，无需公网地址，返回白底图。
已定 UAPI / uapis.cn matting（国内免费抠图 API，符合"全 API / 薅免费额度"策略）； 可替换 本地模型 RMBG-1.4（二级社团工程深化，替换 _call_uapi_matting 一个函数即可）。
为什么不用智谱做去底？ 实测智谱 CogView-4 编辑接口无法可靠保留原产品（输出常重绘）， 而专用去底 API 是 Photoroom/天猫家作/千多AI 等行业工具的真实选择。这一步把 S0 的随手拍变成符合平台规范的主图底版。
2
S2 场景化 / 多版本（Seedream 4.0 参考图生图 · 火山方舟）
把 S1 的白底商品图作为 image 参考传给 Seedream 4.0，prompt 描述"办公桌/户外/车载/礼盒"等场景， 模型在保留产品外观、颜色、材质的前提下生成整图。这是即梦、通义万相、混元等 AI 电商工具的真实链路， 能自然生成"手握杯子"这类无法靠 PIL 贴图实现的交互场景。 已定 Seedream 4.0 doubao-seedream-4-0-250828（免费额度，火山方舟）； 可替换 其它参考图生图 API（二级社团工程深化，替换 _call_seedream_i2i 一个函数即可）。
3
收口 · 质检与交付（V5：构件9质检 + 构件10出片交付（含 WebP） + 构件5归档）
筛选翻车牌（光影/透视错位）、标注 AI 合成、按 SKU 归档、输出交付清单。 即课程 B4 质检筛选 + 合规红线的落点。

4. 构件映射（每章加一个，期末拼成管线）

构件对应阶段教的工程能力
构件0 · 需求解析S0/CSV字符串/正则/dict：brief→结构化 SKU
构件1 · 状态判定内部if/else/for 计数：done/failed/pending
构件2 · 提示词模板S2f-string：商品名+卖点+场景拼装
构件3 · 任务展开内部list/dict：1 个 SKU → N 条任务
构件4 · 封装调用S1/S2函数封装 API、密钥管理、错误处理
构件5 · 归档配置收口pathlib/csv/json：production_log
构件6 · Product 类OOP属性/构造/封装/方法/继承/重写/多态
构件7 · 重试与超时S1/S2try/except：个别失败不崩整批
构件8 · 真实出图S2Seedream API、参考图生图、结构化输出
构件9 · 筛选候选收口“标准化翻译成检查项”、可判定标准
构件10 · 出片交付收口WebP 后处理 + 按 SKU 归档 + README + 标注 AI 合成
关键修正：原"文本编造产品"的 text2img 构件，被替换为真实的 去底 + 图生图 双构件。Python/AI 管线核心技能（API 调用、批量、一致性、质检、归档、交付）一个都不丢，只是从"凭空生成"变成"基于真实产品的扩展"。

5. 案例范本（真实可交付）

流程：学生拍一只真实杯子 → S1 专用 API 去底（保留杯子本体） → S2 Seedream 4.0 参考图生图（把手持/办公桌/户外/车载/礼盒场景） → 收口：质检标注归档（V5）。

评审口径："这能卖吗？" → 能，因为它就是千万商家的日常（家作 13 万商家、慕思省 140 万）。 真实产品 + 真实出图流程，经得起任何追问。

教学彩蛋：S2 生成的图"10 张 8 张能用、2 张翻车（光影/透视错位）"——恰好是 B4 质检模块的真实素材； 合规标注"AI 合成"则是职业红线教学。

6. 合规红线（教学必讲，不得模糊）

红线说明
纯文本编造实物直接上架＝ 虚假宣传，职业红线，我们不教这个。AI 图是展示扩展，不是替代实拍信任。
AI 生成图未标注市场监管总局要求 AI 商品图标"AI 合成"，否则按虚假宣传论处。标注是交付必备构件。
真实产品才能上架学生手里的真实杯子 + AI 扩展图＝合法合规的展示素材，逻辑自洽。
