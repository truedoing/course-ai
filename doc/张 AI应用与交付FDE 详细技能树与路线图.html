三、四条从 JD 与真实案例里读出来、会改变路线的证据

发现一：FDE 在国内真实、大专够得着、正在爆发——这是"对外叫 AI 应用与交付"的 JD 背书

厦门飞书/豆包 FDE 方向 5–8K、大专、应届可投，职责明确写"基于扣子(Coze)搭建行业专属智能体""输出标准化操作手册"；安庆阿里国际站 AI 实施 8–12K、大专应届，硬门槛"熟悉 Python 或 JS 脚本，能独立调试 API"且要"把 AI 逻辑翻译成老板听得懂的生意经"；联想苏州 FDE 10–15K、大专。本科档则跃升至 15–40K（飞书广州 15–20K、猎聘北京 20–40K）。全球侧 FDE 岗位 2026 同比 +729%。

对路线图的直接影响

张对外叫"AI 应用与交付"不是凭空起名，是落到了真实岗位族（FDE）上。大专档（5–15K）是够得着的入口，且筛选的是"做过交付、拿过结果"而非"学历/算法深度"——正好对应张 48 岁、MBA+开发+PM 的复合背景，避开与 25 岁算法工程师的正面竞争。

发现二：定价随"离业务结果距离 / 调用方 vs 实现方"拉开

同一族岗位，薪资跨度从 5K 到 40K，差别不在技术深浅，在责任边界：

5–8K 执行实施（厦门）

"全流程交付实施、账号权限配置、知识库初始化、上门培训、输出操作手册"——关键词：把别人定好的方案跑通。

20–40K 端到端负责（北京）

"将模糊业务需求转化为可实现的 AI 技术方案，完成概念到生产端到端交付；设计复杂 Agent 架构与工作流"——关键词：需求翻译 + 架构 + 兜底结果。

这条是整个路线图的定价逻辑

市场对"翻译业务并兜底结果"的付费远高于"执行既定方案"。张的定位应当锚定中高位（15K+ 档的"方案架构 + 交付"层），靠的是 MBA 的业务翻译力 + 开发底子，而非去卷算法。这也是逆向判据的反面证据："只要求基础语言、不筛经验"的岗定价塌；FDE 恰恰筛经验与结果，所以是可培养目标，不是陷阱。

发现三：真实交付 > PPT 项目（金博 MVP 实证，170h Gap）

张的资料库里有一份基于石家庄本地电梯厂（83 人）真实 AI 落地需求（RAG 技术支持问答）的《金博 AI 落地-MVP 方案与技能 Gap 分析》：8 周 MVP、170h 技能缺口（70h 前置可学 + 100h 共生习得）。

"MVP 阶段只需 JD 描述技术面的 ≈35%；决定性因素是技术选型——选对，80% 工作量从『写代码』降级为『做配置』。而 100h 的 RAG 调优直觉只能靠真实项目喂出来，无法提前学。" —— 金博电梯 AI 落地 MVP 方案（真实企业样本）
对路线图的直接影响

阶段设计里必须嵌一个真实交付样本（校内行政 / 本地中小企业皆可），否则技能树永远停在"会配 Dify"的 L2 执行层。真实项目是护城河"真实交付 × 教学转化"的唯一燃料：没有它，教学内容只能是二手转述，稀缺性塌掉。

发现四：2026 新门槛是"Agent 编排 / MCP / 可观测"，但根不变

北京 Agent 开发 JD 与 2026 行业报告一致显示：Agent 工程师从"写 prompt"升级为"设计规划-执行-反思-人工审批节点""工具 schema 设计""多智能体编排""成本/延迟权衡""Eval 评估管线"。2026 的关键变化是 MCP（Model Context Protocol）成为连接 Agent 与外部工具/数据的标准接口，取代大量 bespoke 集成代码——工程师更多在"评估并安全接入第三方 MCP"而非"从零写连接器"。

这条怎么放进张的路线图

根（工程化素养 + 需求翻译思维）不过期，叶（具体框架/模型）保持会用即可。选型判断力（选对框架/协议）比背框架 API 值钱——这与金博"选型决定 80%"完全同构。张的优势是 20 年开发 + PM 经验，天然在"根"上，只需把连接器重写为 AI-native（API/结构化输出/MCP），不必追每一个新模型。

阶段 0｜连接器重构（第 1–4 周，约 60 小时）

阶段 0 · 连接器重构

第 1–4 周 ｜ 约 60 小时 ｜ 目标：把"会写 Python"重写为"AI-native 连接器"
学什么
不再补语言语法，而是补齐AI 时代连接器：大模型 API 调用（含流式/重试/限流）、结构化输出（JSON Schema/Function Calling）、MCP 协议概念与如何接入第三方 MCP 服务器、向量库基础读写、.env/密钥管理、Docker 基础。本质是把他 20 年开发存量"换成 AI 接口的词汇"。
停止判据（三条全达即停）
① 拿到任意新模型 API，一天内能写出可调通的请求+结构化解析；② 能解释 prompt/结构化输出/Function Calling 的区别与适用；③ 能把一个本地脚本包成 Docker 跑起来。
产出 A（作品）
一套"AI 连接器速查"：覆盖 3 类主流模型 API + 1 个 MCP 接入样例的模板库。
产出 B（教学）
一个 60 分钟模块《从 print 到 API：高职生也能接大模型》——直接复用为一级底座"模块 A 调接口"的备课素材。

阶段 1｜管线工程主线（第 5–20 周，约 200 小时 · 核心）

这是整条路线价值中枢。目标是把"一次性脚本"长成"可批量、可并发、可质检、可归档"的管线——manhua.py 的十构件就是这条主线在课内的投影。

阶段 1 · 管线工程

第 5–20 周 ｜ 约 200 小时 ｜ 这条不过关，阶段 2/3 不成立
1.1 批处理与并发
从"跑一条"到"跑一万条"：任务队列、并发控制、失败重试、成本统计。对应 manhua.py 构件 9（批量出图）。
1.2 一致性与质检
把"看着对不对"翻译成可勾选判据（manhua.py 的 consistency_score 与 pick_best）。这一层是张与董老师接口的所在：他出"图"，她定"图算不算合格"，但质检脚本由他实现、验收清单由她定。
1.3 版本与归档
产物命名规范、版本号、生产日志（manhua.py 的 production_log.csv 与 meta.json 三态 status）。这套契约是未来与 JS 工具组、与董老师资产包对齐的文件接口。
产出 A（里程碑作品）
一条可复用管线：输入 SKU 清单/需求 brief → 批量出图 → 自动质检 → 输出合格素材包 + 生产记录。它既是课内教具，也是未来 FDE 交付的雏形。
产出 B（教学）
一门 3 小时课《把一次性脚本变成生产线》——直接对应二级训练营 B1–B5 工程能力。
验收判据
① 丢 100 条任务进去，零人工干预跑完；② 把管线文档给一个没学过的人，他能按文档复现。

阶段 2 · 智能体与知识库

阶段 3｜交付与实施（第 17–36 周，约 180 小时）

阶段 3 · 交付与实施

第 17–36 周 ｜ 约 180 小时 ｜ 把"能做"变成"能交付、能验收、能讲清"
交付三件套（JD 高频但最易被忽略）
①实施方案（需求调研 → 场景拆解 → 技术选型 → 落地计划）；②培训手册 / SOP（分层培训计划 + 标准化操作手册，厦门 JD 原话）；③验收报告（准确率/节省工时/边界说明）。金博的 30%/40%/30% 里程碑结算 + Phase 0 单独立项是范本。

客户边界管理
把"MVP 边界写进合同""哪些不做"写清楚，避免无限兜底。这一点金博文档已给出可复用模板。

阶段 4｜验证与产品化（第 29–52 周，约 240 小时）

阶段 4 · 验证与产品化

第 29–52 周 ｜ 约 240 小时 ｜ 内部自嗨与外部验证的分界线
核心动作：2–3 个外部真实项目
不是模拟题，是别人付钱或至少愿意署名的项目（校内部门 / 本地中小企业 / 电商商家均可）。作用是把阶段 1–3 建立的规范放到不认识的人手里验证——只有这步能回答"我的方法是通用方法，还是只有我自己跑得通"。

把课程内容分"不变内核"（需求翻译逻辑、交付模板结构、验收判据）与"季度外壳"（具体框架截图/模型名）两层。每次模型迭代只重做 20%。

FDE 的买单方横跨：① 企业服务商（飞书/字节/原厂，需要能把产品落地到客户业务的人，厦门/广州/苏州 JD 即此）；② 传统企业（安庆阿里国际站、金博电梯这类"AI 落地需要但没人愿干/不会干的活"，不在 985 筛选体系）；③ 院校与培训市场（需要"真做过交付、还能讲清楚"的讲师）。

张的特殊杠杆：高职教师身份让他能以"产教融合/校企合作"拿到前两类客户以低价甚至免费给的机会——纯自由职业者拿不到这种产业入口。这是 OPC 视角下"教育身份"的隐藏价值，不要当包袱。

九、季度自检与纠偏

每季度做一次，对照六条。前三条任一不过关，说明路线偏了，退回上一阶段重做，不要继续往前。

  1. 外部性检查：本季有没有至少一件东西被不认识的人使用或付费？没有 → 停在自嗨边缘，立刻补真实样本。
  2. 复现检查：把管线/模板文档给一个人按着做，他能做到吗？不能 → 交付的是手艺不是标准，定价会被锁在 L2。
  3. 不可替代性检查：本季学的东西，一个刚毕业的计算机本科生三个月能不能追上？能 → 这项投入白费，砍掉。
  4. 双产出检查：每阶段"项目作品"和"教学模块"都产出了吗？只有一边 → 半年后要么没作品、要么没内核。
  5. JD 对照检查：重新抓 10 份最新 FDE JD，看正在学的还在不在。工具/框架类一旦消失，立刻降优先级。
  6. 定价检查：产出是在"自己干执行"（拿 5–8K 价），还是在"翻译业务+兜底结果"（拿 15K+ 价）？一直在前者 → 阶段 3 没真正过关。

十、最需要警惕的两条路径

失败路径 A：停在工具层做"全能 AI 讲师"

表现：什么框架都会接，课也讲得热闹，但回答不了"怎么保证一个企业知识库问答准确率达标、怎么交付验收"。
为什么失败：这个位置供给庞大、价格被压（厦门 5–8K 即此档）。强模型/框架半年一代，每年重做，积累归零。张的 MBA+交付经验若只用来讲工具，是降维浪费。

失败路径 B：只有 PPT 项目，没有真实交付

表现：知识量很大，讲什么头头是道，但拿不出一个别人能用、能验收的真实交付案例。
为什么失败：阶段 2 的"真实项目喂养"没过。这一条不过，护城河"真实交付×教学转化"塌掉——而那是张相对于纯 AI 讲师、纯工程师的唯一稀缺点。

纠偏：现在就停掉纯学习，回到阶段 1/2，把一个真实交付做完整做完整做完整。
