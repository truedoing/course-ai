序：这份手册怎么用

体系设计那一份解决的是"三级为什么这样分"，这一份解决的是"每一级具体教哪些东西、学生练完能做什么、怎么算过关"。

三级共用同一套结构，每一级都按这六件写：

  1. 能力清单——编号的能力项，每条都用"能做什么"而不是"学过什么"来写；
  2. 训练内容与课时——模块划分与周次落点；
  3. 任务卡——每个训练任务的目标、输入、产出、判据；
  4. 周表——每周当堂做什么、交什么；
  5. 验收量表——不合格 / 合格 / 优秀三档，各档长什么样；
  6. 教师准备与失败纠正——这一级最容易塌在哪、怎么提前防。

贯穿三级的一条原则：能力项必须能用一条可观测的证据来证明。"掌握 Python 基础"不能验收，"给定 shots.json 前三条，写出状态判定并输出正确"可以。下面所有判据都是后者——这也是期末评分、以及一年后面试时学生能讲出东西的前提。

一、任务卡：所有训练任务的统一格式

三级共用一张卡，任何一次训练任务都按这五项写清楚。写不出"判据"的任务不要布置——没有判据的任务，学生交上来你只能凭感觉打分，一周后就变成走过场。

连接器三块的细化（共 10 学时，含在 60 之内）

A2调接口 4 学时

  • 讲什么：HTTP 请求与响应的形状、JSON 结构与取值、状态码含义、密钥放环境变量、超时与重试的基本写法。
  • 练什么：先给一个 mock_server.py（返回固定 JSON，不联网），学生练请求构造与字段解析；跑通后换真实地址，只改一个常量。
  • 判据：真实调用成功一次，提交调用记录；代码里搜不到密钥字符串。
  • 教师准备：mock 脚本一份（约 40 行）、两个平台账号与额度、一份"常见状态码对照表"。

A3文件批处理 4 学时

  • 讲什么：路径遍历、批量重命名规则、PIL 改尺寸与加水印、调用 ffmpeg 命令行做帧与视频处理。
  • 练什么：给 100 张尺寸不一的图，统一成三种平台规格（主图 / 详情 / 封面），输出 manifest.csv。
  • 判据：100 进 300 出，行数对得上；清单里有原文件名、新文件名、尺寸、处理时间四列。
  • 教师准备：100 张素材（公开图库即可）、三种平台尺寸规范表、ffmpeg 安装包与一条现成命令。

A4Git 与虚拟环境 2 学时

  • 讲什么：只讲三件事——提交、回退、看历史。分支模型不教，够用即可。附带 requirements.txt 与虚拟环境。
  • 练什么：故意让脚本跑挂一次，用回退找回上一版能跑的代码。
  • 判据：提交记录里看得到十个零件的演进；同桌互相 clone 一次，照 README 跑通。
  • 教师准备：README 模板（含环境、安装、运行、常见报错四段）、一个故意留错的样例仓库。

2.3 第一级的验收量表

维度不合格合格（给学分）优秀
跑通只能在自己电脑上跑，换机器就报错仓库发给别人，照 README 一次跑通别人跑通且无需提问
批量一次只能处理一个，手动重复一次处理 30 个，有清单有失败重试与跳过，30 个全部有结果
记录没有记录，或只写"完成"有参数、耗时、废片数能算出单位成本并说明瓶颈在哪
报错看到红色就举手能定位到行能区分三类错误来源并给出改法

这一级最大的风险不是学生学不会，是期末倒逼回传统教法。防线只有一条：知识点一个不删，只换案例载体——学生考的仍是 f-string、推导式、try-except，不因载体变化承担任何笔试风险。新增的 16 学时赛道内容不进闭卷，全部挂在"上机 20%"上；不计分学生就不重视，这是 16 学时最容易打水漂的地方。

2.4 JS 班在这一级的位置

注（2026-09-18 修正）：本节原默认 JS 与 Python 两侧底座一致。实际 JS 两个班的 Python 由其他老师任教、未改造，因此两侧不再咬在"同一套 Python 能力"上，改为咬在数据契约上。本节表格中的接口约定仍然有效，具体协作机制见《JS 两班并入训练营的协作机制》。

两个语言底座不是两个专业方向，是同一条生产线的两端：Python 造引擎，JS 造控制台。JS 侧对应学时应讲的是：

JS 侧内容对应能力与 Python 侧的接口约定
fetch 与异步等同于 A2 调接口同一套接口地址、同一份 JSON 结构、同一种鉴权方式
表单与任务队列界面把参数表变成人能填的界面输入就是 shots.json / sku.csv，字段两边一致
素材库与审核界面把 B4 质检变成可点选的工具读取同一个 runs/ 目录与 manifest，不做第二套存储
数据看板把 C3 成本产能可视化读同一份生产记录 JSON

两边必须讲同一套"连接器"口径——调接口、JSON、鉴权、错误处理四个词在两门课里含义一致，第二级才有共通语言。至于第 12 周之后的分轨：Python 班造引擎，JS 班造控制台，大二下合流成一个完整工具。

B2 和 B4 是这个方向的立身之本，也是工资分水岭所在。2026 年 9 月在招 JD 里，两份都叫"美术指导"、同在重庆、工具要求几乎相同的岗位，薪资差 6–8K 与 15–25K 三倍；差别就在"建立并维护资产库、推动美术标准体系化、审核他人产出"这半套职责上。B2 是能产出一致的结果，B4 是能判断什么算合格——这两条合起来，就是那半套职责。

3.3 五项能力的训练任务卡

B1批量与并发

目标：把"点一百次"变成"跑一次"。输入：一张含 100 条提示词的 CSV。产出：100 张图 + 一份结果表（成功/失败/耗时/重试次数）。判据：合格 = 全部有结果且不中断；优秀 = 中断后能从断点续跑，不重复消耗已成功的任务。

常见错误：不设间隔被平台限流、失败即崩、把 100 个任务写死在循环里没有队列概念。

B2一致性控制

目标：让 10 张图像同一个对象，并说清锁了什么。输入：一张基准参考图 + 5 个不同动作描述。产出：10 张图 + 锁定变量表（参考图、种子、风格词、光照词、权重）。判据：合格 = 外观可辨认为同一对象；优秀 = 换人执行同一份锁定表，结果接近。

常见错误：只锁参考图不锁风格词；把"像不像"当感觉而不是可对照的参数。

B3归档与版本

目标：三个月后还能找回任意一张图的全部参数。输入：前八周产出的所有散落文件。产出：规范目录 + index.json + 版本号规则。判据：合格 = 抽 3 张能给出参数；优秀 = 目录结构换人也能看懂，附一页规范说明。

常见错误：文件名用中文和空格、图与参数分开放、版本号随手写。

B4质检与筛选

目标：把"我觉得不行"变成可执行的判断。输入：一批 30 张候选。产出：3–5 条标准条文 + 筛选结果 + 废片率。判据：合格 = 标准可判定（不出现"好看""有质感"）；优秀 = 标准能被另一个人执行且结论一致。

常见错误：标准写成审美描述；只挑好的不记录废片，导致废片率永远是未知数。记住：我们的活不是替美术下判断，是把别人已作出的判断翻译成可执行、可复用、可批量验证的检查项。

B5工作流封装

目标：换素材不改代码。输入：一份新的素材表。产出：一条命令 + 配置文件。判据：合格 = 换素材后只改配置；优秀 = 附带一份操作说明，同组人照做能跑出同样结果。

常见错误：路径写死、参数散落在代码各处、没有说明文档导致只有自己会用。

3.4 寒假与大二下

寒假三个任务包（降频，每两周线上检查一次）：

  1. 把一件手动做过的事写成脚本——参数化、可复现，正好接课内第 8 章；
  2. 建立自己的资产库——角色、场景、风格整理成目录规范 + JSON 索引，这是做长片的前提，也是简历上能写的一条；
  3. 拆 3 部热门作品的分镜——交一份拆解表（镜头数、节奏、转折点）。不消耗算力，但决定下学期选题的眼光。

3.5 第二级的验收与失败判据

唯一判据：学生能不能独立跑完"需求进来 → 素材出去 → 有记录"这条线。

能，就进第三级。不能——哪怕学生很积极、氛围很好、作品也好看——说明这级教成了兴趣小组或工具课。第 8 周必须自查一次，不要等到期末。

维度不合格合格优秀
独立性要老师一步步带着才能出图给定需求能自己跑完整条线能带一个新人跑一遍
可复现只交成品，说不出参数有参数记录，能重跑换人照记录能跑出接近结果
一致性每张都像不同对象10 张可辨认为同一对象锁定变量表清晰，换人可执行
量化说不出花了多久、废了多少有耗时与废片率能算出单位成本并指出瓶颈环节

四、第三级：核心项目组（10–12 人 · 大二下出作品）

4.1 能力清单 C1–C5：分叉的那两成 + 工程化

编号能力行为描述验收证据
C1管线封装与断点续跑把多个环节串成一条链，任一环节失败可单独重跑，不推倒重来在中间环节人为断电一次，恢复后能从断点继续
C2标准翻译成检查项把"这个不行"翻译成可自动执行的判定（尺寸、主体占比、相似度阈值、水印、格式）一份检查项清单 + 一段自动检查脚本或工具；他人可执行且结论一致
C3成本与产能核算能报出"100 张要多久、多少钱、几个人、瓶颈在哪"成本核算表 + 产能测算；与实际支出误差在 20% 以内
C4分工与责任归属把一条线拆成可归属的责任段，定义清每段输入输出责任分配表 + 接口约定（文件名与格式）；每人能说出自己那段
C5交付与对外沟通能与需求方确认样品、走验收、留修改记录；能与平台过审要求对表需求确认单 + 验收单 + 修改记录；一次通过或有据可查的修改闭环

4.2 分叉的两成：电商侧与漫剧侧各练什么

环节电商素材管线漫剧生产管线
输入SKU 表、白底图、平台尺寸规范剧本、角色设定、分镜参数表
专项内容字段映射与批量读取；三平台尺寸与命名规范；去背与换背景；多角度一致性；平台过审红线（文字占比、绝对化用语、logo 位置）角色卡与参数表 JSON；分镜表字段（镜头号、景别、运镜、时长、提示词）；图转视频的首尾帧控制；音画合成与字幕规范
一致性对象同一件商品十个角度像同一件——材质、色彩、logo 位置同一个人五十集像同一个人——脸、服装、色调
交付结构上架包：目录规范 + 命名规则 + 元数据 + 过检自查表成片包：分辨率码率规格 + 字幕 + 封面 + 投稿信息表
质检口径可量化：点击率、转化率、平台过审率半量化：废片率、一致性达标率、单集耗时
人均算力约 120 元约 550 元
出口AI 设计师 4–6 千 → 搭工作流 10–12K抽卡师 4–6 千 → 管线工程 25–40K

两条管线共用同一个脚本的前六个零件——第 8 章的 Product 类和 Character 类其实是同一个类的两个实例：都是一个"基准资产 + 参数表 + 质检标准"的对象。讲一个，另一个当作业。这也是为什么第二级教的是共享的八成——分叉的这两成，真到第三级只需要几周就能补上。

4.3 三个岗位位

第 11 周自选后，12 人左右会自然分化。两个管线组之外，一定要留第三个位置：

位置人数练什么为什么必须有
电商管线组4–5 人SKU 批量、平台适配、上架包交付链条短、见效快，是接单与现金流来源
漫剧管线组4–5 人角色卡、分镜、图转视频、音画合成链条长，是作品集的高度所在
资产与规范组2–3 人资产库维护、归档规范、成本台账、质检清单真实团队里这个位置存在且重要；也接住了"两边都不选但一直在交付"的那批人

4.4 大二下四阶段任务表

阶段时长任务交付与判据
P1 管线成型3 周把手动流程串成一条链，加断点续跑与日志链条脚本 + 一次人为中断恢复演示
P2 标准落地2 周请视传/数媒老师给判断，学生把它翻译成检查项并自动执行检查项清单 + 自动检查；两人执行结论一致
P3 批量生产4 周按责任段分工生产，跑通后轮换；全程记台账10 集成片 / 一套完整素材包 + 责任段说明
P4 交付与复盘3 周投稿或交甲方，跟踪数据，做成本核算作品 + 生产记录 + 成本核算表 + 个人作品集

第三级要交的不是作品，是"生产记录"。成片当然要交，但真正体现工程能力、也真正能在面试里讲的东西是另外一份：工作流版本号、废片率、单集（单 SKU）耗时、成本核算、遇到的问题与改法。

顺德那条 10–12K 的 JD 问的是"这条线能不能自己跑"，不是"这张图好不好看"。能拿出这份记录的学生，已经能和只会出图的应聘者区分开了。

七、三级各自的失败方式与纠正动作

级别最可能的失败方式纠正动作
一级期末闭卷倒逼回传统教法，改造半途而废知识点一个不删、只换载体；赛道内容不进闭卷；先确认是不是教考分离，这条不问清方案就悬着
新增 16 学时学生不重视挂到"上机 20%"上计分；零件交付折算进平时分，不计分等于没做
二级滑成工具课或兴趣小组第 8 周自查一次："能不能独立跑完需求进来→素材出去→有记录"；不能就砍掉花哨内容，回到批量与归档
人数流失到个位数按招 30 留 12 设计，30%–40% 留存是正常水平；门槛前置比事后掉人好得多
算力不到位第一周就停摆四条路同时走：平台教育扶持、本地商家预付款、社团经费、企业共建
三级拖到期末才开，来不及出作品第 11 周必须定人，寒假远程做脚本化；大二上末不完成这一步，大二下必然赶工
只有小组署名，个人作品集空每人另交一份"我负责的环节 + 生产记录"；漫剧按组组织时务必拆到可归属的责任段

最后一句：三级加起来十五个能力项，学生能拿出证据的项数，就是一年后他作品集的厚度。面试时掏出来的是一个链接和一份能讲清废片率与成本的生产记录，不是一张成绩单。这一年窗口里所有的时间分配，都该按这个标准排序。
