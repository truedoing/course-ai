AI 培训体系 · 总纲（收口文档）

AI 培训体系总纲：三版块 × 双技能树 × 路线图

把"三级火箭"交付机制与"三版块"课程内容收口成一套体系；明确张（技术底座+AI 交付）与董老师（AIGC 应用路线）各自的定位、技能树、路线图；学生按发展分轨训练。所有技能项均回溯到真实 JD。

体系一句话

三版块 = AI 应用与交付（FDE，张主导） + AIGC 电商（董老师视觉标准+张管线） + AIGC 短剧（董老师主导）。三级火箭 = 一级语言底座（课内全体必修）→ 二级训练营（社团志愿，分三轨）→ 三级核心项目组（真实交付，7-8 人自组织）。课内教"分叉之前的那段"，二级把八成主干放大成工程能力，三级放真实交付——同一条线被放大三次，不是教两遍。

二、张的技能树与路线图（技术底座 + AI 交付实施）

定位：AI 落地架构者 / 交付框架搭建者（国内岗名=AI 应用交付工程师 / FDE）

不是"写模型的人"，是把一次性判断翻译成可复用、可交付东西的人（腾讯研究院第四层判据）。市场侧证据：FDE 是国内真实、大专够得着、且正在爆发的岗位（见第六节）。张的护城河 = 真实交付 × 教学转化——市场绝大多数 AI 课讲师没做过真实企业项目。

真实交付锚点：金博电梯 MVP（170h Gap 实证，锚定技能树 C/D 枝）

张的资料库里有一份基于真实企业的《金博 AI 落地-MVP 方案与技能 Gap 分析》：目标企业是石家庄本地电梯厂（83 人）的真实 AI 落地需求（技术支持问答 RAG），给了 8 周 MVP、170h 技能缺口（70h 前置可学 + 100h 共生习得）。这正是 FDE 路线"做过一次"的实体样本，且就在本地——也是 FDE 真实客户源的高优候选（见执行基线 v1 客户源待定项）。

技术栈 ↔ 技能树映射：

  • 枝A 连接器：企微机器人接入、Dify API 扩展、Docker Compose 部署（张的 Linux/Docker 老家底直接接上）
  • 枝B 管线与工程：Dify 工作流编排（与 Coze/n8n 同层，"能托管不自研"原则）——补了原树只列 Coze/n8n 的盲区
  • 枝C 智能体与知识库：RAG 全栈 = bge-m3 向量化 + pgvector + bge-reranker + RAGAS 评测 + MinerU 文档解析——把原树"RAG/向量库/Agent"从名词落成具体选型
  • 枝D 交付与实施：MVP 边界写进合同、Phase 0 单独立项 + 里程碑结算（30%/40%/30%）、验收报告含准确率/节省工时——"交付表达"的真实范本

关键判断（来自该文档）：MVP 阶段只需 JD 描述技术面的 ≈35%；决定性因素是技术选型（选对，80% 工作量从"写代码"降级为"做配置"）。这印证张的护城河="真实交付 × 教学转化"——而 100h 的 RAG 调优直觉只能靠真实项目喂出来，无法提前学。另：该案例的评测集/脱敏数据可直接变成期刊实证素材（产教融合数据），是 OPC 双重收益的体现。

三、董老师的技能树与路线图（AIGC 应用路线）

定位：AI 内容的视觉资产架构者（AIGC 应用路线负责人）

她不是做内容的人，是定义内容如何被生产的人——定义标准、验收质量、传递标准（对应 UI 规范力、设计师判断力、教师身份三块存量）。在三版块里，她覆盖 AIGC 电商（素材视觉标准） 与 AIGC 短剧（角色一致性+分镜） 两条线的视觉标准层，不碰 FDE（那是张的主场）。以下技能树来自 2026-09 实抓的 22 份 JD 逐条拆解。

四、双线主副配合（分工边界写死）

张负责（技术底座+FDE）

全局设计、连接器、批处理/并发、一致性管线、质检脚本、文件契约、智能体/工作流搭建（Coze/n8n/ComfyUI API）、FDE 部署与交付文档。
判据："怎么批量跑、怎么交付"归他。

董老师负责（AIGC 应用路线）

电商+短剧的视觉标准：角色卡、验收清单、一致性判据、分镜评审。"什么算合格"归她。
判据：她能独立对甲方说清理由=她的；只能说"张说好"=越界。

红线

张不替董老师定视觉标准——她一旦变成"你说怎么做好就怎么做"，内核就废了（那是她唯一不可替代的东西）。董老师不钻工程实现——脚本/部署由张承担，她只需"能用、能讲、能验收"。两人之间的接口 = manhua.py 的 meta.json（status 三态 + score）与资产包规范文档。

七、三版块如何共享底座（避免重复造轮子）

共享段（一级+二级前半段，三轨同练）：连接器（调 API/读报错）、批处理与并发、一致性判据、质检筛选、文件契约（meta.json 三态）。这一段就是 manhua.py 长出的能力，与"选 A 电商素材"共用同一 Product 基类——短剧角色是它的子类，FDE 的智能体是它的"批量任务"变体。

分叉段（应用层，按轨深化）：

  • FDE 轨：把"批量任务"接成 Coze 智能体 + 部署配置 + 交付文档（张）
  • 电商轨：把"批量任务"接成白底/场景/细节图生产 + 平台质检清单（董老师视觉+张管线）
  • 短剧轨：把"角色"接成 LoRA + 分镜 + 图生视频（董老师）

结论：不是三个独立课程，是一条主干上长三个应用头。这既控制精力（张只维护主干+FDE头，董老师维护两个AIGC头），又让学生"换应用不换底层"——这正是体系可规模化的根。
