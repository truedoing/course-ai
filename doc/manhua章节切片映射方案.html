manhua.py 章节切片映射方案

一级底座 · Python 课程改造 · 综合案例切片总纲（配套学生版构建指南 V1–V5）

螺旋式课程母体一致性零环境依赖

一、为什么切片

manhua.py 是课程综合体，但 V1 一起步就同时踩到：文件读写 + HTTP 请求 + base64 编码 + 环境变量 + 异常处理。刚学完 if/for 的学生直接上，会被一堆陌生符号淹没——他不是不会分支循环，是认知过载。

解法对应两个经典原理：螺旋式课程设计（Bruner，同一母体的复杂度逐轮上升）与认知负荷控制（Sweller，每步只叠加一个新技术点）。本方案把综合案例按 Python 课程章节切成微案例，最后再组装。

二、三条硬约束（贯穿所有切片）

1. 母体一致性（成败关键）

切片里写的函数名 / 变量名 / 类，必须和最终 manhua_studio 里一致：

  • 第 4 章写 build_scene_prompt(name, selling_point, scene)
  • 第 7 章写 parse_products_csv / 商品数据结构
  • 面向对象章写 class Product（含 .score 方法）

这些名字在综合阶段原样复用。反面教训：切片里随便起名、综合阶段又换一套 → 等于白切片，学生面对的是另一套陌生代码。

对齐说明：真实母体 manhua_studio/prompts.py （master 完好）已定义 build_scene_prompt(name, selling_point, scene) 与 DEFAULT_SCENES（V2 引入提示词、V3 加平台规范）。第 4 章切片即逐字复刻此函数，综合阶段学生直接从 manhua_studio.prompts import 同名函数，零跳变。（此前误判"V5 删除 prompts.py"系工作树曾 detached 在 v1 所致，v1 本就无 prompts.py。）

2. 零环境依赖（切片阶段）

第 4 章纯字符串、第 7 章用本地假 SKU 数据，都不要求配 key / 联网。真实的 requests API 调用 + .env 密钥，全推到综合阶段。这正好把"V1 涉及 HTTP/文件/key 认知重"的痛点整个挪到最后一关。

3. 切片不碎

每个切片末尾加一个「母体映射」框，显式说清"这个练习 = 综合案例里的构件 X"，保持全局感，否则切片变散沙。

四、每台阶「母体映射」话术示例

第 4 章下课："你写的 build_scene_prompt 就是综合案例里拼提示词的那一步——到时候它会被 S2 出图直接调用。"
第 7 章下课："你解析的 SKU、写的 JSON，就是综合案例构件 0 / 构件 6 的输入输出格式。"
面向对象章下课："你这个 Product 类，综合案例里要带 .score 方法做质检。"
